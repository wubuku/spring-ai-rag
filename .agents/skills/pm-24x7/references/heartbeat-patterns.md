# HEARTBEAT.md 模式

## 为什么需要 HEARTBEAT.md

OpenClaw cron 会话是**隔离的**——每次运行都是全新启动，没有之前运行的记忆。HEARTBEAT.md 是桥梁：一个在 context reset 后依然存在的持久化文件。

## 三层结构（生产验证）

真实项目使用三层结构：

### 第一层：核心铁律（文件顶部）
不可妥协的原则。Agent 每轮都读。

```markdown
## 🔴 核心铁律
1. **7×24 不停歇** — 不等指令
2. **测试驱动** — 每个改动必须过测试
3. **回归测试必须跑** — 每次改动后运行回归测试
4. **文档跟代码** — 更新代码同步更新文档
5. **诚实报告** — 报告失败，不掩盖问题
```

### 第二层：巡检清单
每轮 cron 的有序步骤。

```markdown
## 🟡 巡检清单
1. 构建检查：`./precompile.sh && cd Dddml.T4.ProjectTools && dotnet build`
2. 运行测试：`dotnet test DDDML.NET.sln`
3. 查看当前任务 → 有活跃任务则继续，没有则扫描改进点
4. 轮换关注领域（轮 A/B/C/D 依次循环）
5. 发现问题立即修复，修复后重跑测试
6. 提交并汇报
```

### 第三层：任务看板和进度
当前任务、质量基线、进度日志。

```markdown
## 🟢 当前任务
[正在做什么]

## 质量基线
- 构建: ✅ 通过
- 测试: 176/176 ✅
- 上次审查: 2026-03-30

## 进度日志
- ✅ 2026-03-30 11:30 代码质量审查
- ✅ 2026-03-30 03:09 背压机制
```

## 最小可用结构

如果不能用全部三层，至少有：

```markdown
# HEARTBEAT.md

## 当前任务
[一句话：我正在做什么]

## 任务看板
| 任务 | 状态 | 备注 |
|------|------|------|
| 功能 A | ✅ 完成 | 2026-03-20 |
| 功能 B | 🔄 进行中 | 写测试中 |
| 功能 C | ⏳ 排队 | 被 B 阻塞 |
```

## 状态符号

统一使用：
- ✅ 完成 — 已完成并验证
- 🔄 进行中 — 正在做
- ⏳ 排队 — 准备好开始
- ⏸️ 阻塞 — 等待某事
- 🔴 失败 — 尝试但失败（包含原因）

## 高级模式

### 模式一：阶段轮换
大型项目轮换关注阶段：

```markdown
## 审查轮换
当前关注：阶段 2（上次审查：2026-03-20）
- 阶段 1：上次审查 2026-03-19
- 阶段 2：🔄 正在审查
- 阶段 3：上次审查 2026-03-18
- 阶段 4：上次审查 2026-03-17
```

### 模式二：质量指标
跟踪质量趋势：

```markdown
## 质量基线
- 测试: 176/176 通过
- 覆盖率: 82%
- Lint 警告: 3
- 上次全面审查: 2026-03-20
```

### 模式三：决策日志
记录决策供未来参考：

```markdown
## 决策
- [2026-03-20] 选择 HNSW 而非 IVFFlat（查询性能更好）
- [2026-03-19] 最小相似度设为 0.7（减少噪声）
```

### 模式四：错误恢复
记录出错和修复方式：

```markdown
## 近期修复
- [2026-03-20] 修复 ApiClientService NPE — 添加空值检查
- [2026-03-19] 修复线程泄漏 — 用 Spring bean 替换 Executors.newFixedThreadPool
```

## 反模式

### ❌ 任务卡住
```markdown
| 任务 | 状态 |
|------|------|
| 修复 Bug X | 🔄 进行中 |  <!-- 卡了 5 天！ -->
```
**修复**：卡住超过 3 轮就升级或重新拆分。

### ❌ 每轮重写
```markdown
<!-- Agent 每次都重写整个文件 -->
```
**修复**：只更新变化的行。保留历史。

### ❌ 模糊任务
```markdown
- 提高代码质量
- 让它更快
```
**修复**：具体化："审查 AlertServiceImpl 的 NPE 风险"，"基准测试查询延迟"

## 状态转换

```
⏳ 排队 → 🔄 进行中 → ✅ 完成
                    ↓
                🔴 失败 → ⏳ 排队（重试）或 📝 已记录
```

## 自包含规则

另一个 agent 实例只看 HEARTBEAT.md 应该能：
1. 理解项目当前状态
2. 知道继续哪个任务
3. 知道最近做了什么
4. 知道什么被阻塞、为什么

如果任何一点不清楚，文件需要改进。
