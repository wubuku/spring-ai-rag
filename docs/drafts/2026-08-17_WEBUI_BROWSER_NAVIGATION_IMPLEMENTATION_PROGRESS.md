# WebUI 浏览器导航可用性改进进度

> 状态：已完成
> 更新时间：2026-08-17

## 1. 任务目标

修复 WebUI 中页面跳转、浏览器前进/后退和刷新不能可靠恢复页面上下文的问题。重点场景是：

1. 在 `/webui/search` 执行搜索；
2. 从搜索结果打开文件管理中的目录或索引文件；
3. 使用浏览器后退回到搜索页；
4. 搜索条件和结果仍然可恢复，而不是回到空白搜索页。

本任务不改变 RAG API、数据库 schema、鉴权模型或文件来源追溯协议。

## 2. 当前代码事实与已确认根因

- 前端使用 React Router `BrowserRouter`，生产 basename 为 `/webui`。
- 搜索结果由 `Search.tsx` 的 React state/TanStack Query 保存：
  - 查询输入、Hybrid 开关、集合范围、已搜索状态没有进入 URL；
  - 页面卸载后重新挂载时没有可恢复的搜索请求描述；
  - 因此从文件管理页后退到搜索页时结果消失。
- 文件管理页的深链接可以读取 `path` 和 `file`，但内部目录点击、文件选择没有更新 URL：
  - 浏览器无法记录文件管理页内的目录/文件导航；
  - 同一页面内后退不会返回上一个目录或文件预览。
- `Documents.tsx` 目前只在首次挂载时读取 `collectionKey`；集合筛选、关键词、分页等交互状态主要是局部 state。
- Chat、Alerts、Evaluation、ABTest 也存在局部视图状态；本次先按“用户可定位的页面上下文”审查，不把临时弹窗、表单草稿、拖拽状态强行写入 URL。

## 3. 方案边界

### 3.1 写入浏览器历史的状态

- 搜索：已提交的查询、Hybrid 模式、集合范围和集合 key。
- 文件管理：当前目录、当前预览文件和导入时间排序方向。
- 其他页面：只有在代码审查和回归测试证明低风险时，才加入已有页面的筛选、分页或可定位视图状态。

这些状态使用 URL query 参数表达，保证：

- 后退/前进触发 React Router 位置变化；
- 刷新或直接打开深链接可以重新发起必要的 API 请求；
- 不把 API key、原始文件内容或敏感数据放入 URL。

### 3.2 不写入浏览器历史的状态

- 模态框开关、上传中的临时状态、表单未提交草稿、菜单展开状态、hover/focus 状态；
- 不具备稳定后端标识的流式中间内容。

## 4. 保护工作区约束

- 本任务开始时工作区已有“文档管理操作菜单与文件/PDF 来源追溯”未提交修改。
- 不使用 `git stash`、`git reset --hard`、`git checkout --` 或其他会丢弃/覆盖修改的命令。
- 只修改本任务需要的文件；发现其他开发者改动造成测试阻塞时，只做最小测试适配，不改动其业务实现。
- API key 不写入本文档、源码、测试快照或 git。

## 5. 实施计划

1. 让搜索 URL 成为已提交搜索的可重放描述，并在返回/刷新时自动恢复结果。
2. 让文件管理目录和预览文件导航使用 Router history，支持目录内后退/前进和深链接恢复。
3. 根据代码审查结果，补充高价值页面上下文的导航回归测试；不为低价值临时 UI 状态扩大范围。
4. 补充 Vitest 和 Mock Playwright 验收：
   - 搜索结果 -> 索引文件 -> 浏览器后退 -> 搜索结果恢复；
   - 文件目录 -> 文件预览 -> 后退 -> 目录恢复；
   - 刷新带 query 的搜索/文件深链接；
   - 前进/后退不引入错误 URL 或 API 请求。
5. 执行前端类型检查、生产构建、单元测试、lint/alignment 和核心 Playwright。
6. 基本验证通过后进行三轮固定范围代码复查；发现实质问题立即修复并重新验证、重置复查计数。

## 6. 验收矩阵

| 场景 | 期望 |

| `/webui/search` 提交查询 | URL 含可重放的非敏感搜索参数 |
| 搜索结果打开索引文件 | 进入 `/webui/files?path=...&file=...` |
| 从索引文件后退 | 回到搜索 URL，结果自动重新加载并可见 |
| 文件目录打开文件再后退 | 回到目录，文件预览关闭 |
| 刷新搜索 URL | 搜索条件和结果重新加载 |
| 刷新文件深链接 | 目录和目标文件预览恢复 |
| 侧边栏/集合导航 | 既有 URL 导航不回归 |
| API key | 不出现在 URL、文档或测试输出 |
